大模型推理 · KV Cache

为什么留下 K 和 V，却把 Q 放下？

AI 每写一个字，都要回头看前面所有的字。KV cache 就是把「回头看」要用的东西存起来。

这里的「字」指 token：模型处理文字的小单位。

01

每写一个字，都要从头再算一遍吗？

不用。算过的 K/V 留着，新字只算自己那一份。

先把输入「今天天空是」读完（prefill）：3 个字的 K/V 一起算好，存进缓存。选出第一个新字「蓝色」——它的 K/V 还没有，要等它被送回模型才算。

旧字的 K/V 算一次，一直用；每步只给新字算一份。

02

Q、K、V 分别是什么？

每个字进到一层 attention，都会被变成三份东西。

新字拿自己的 Q 去对每个字的 K；对得越上，就拿越多那个字的 V。

03 · 关键

为什么留下 K/V，却不留 Q？

把每一步「谁读了谁」画成一张表：

蓝色那一行：「蓝色」的 Q 只用一次。绿色那一列：「天空」的 K/V 被后面每个字反复读。

outputt = softmax( qt只有现在这一个 K≤t⊤从头到现在全部 / √d ) · V≤t从头到现在全部

Q 只用一次 → 不用存。K/V 以后还要被读 → 存起来。所以叫 KV cache。

04

新字进来的那一步，到底算了什么？

然后 q 就退场了；k、v 留在书架上，等下一个字来读。

k、v 先进缓存，所以 q 也能看到「蓝色」自己。head 的输出还要经过后面很多计算，才变成下一个字的分数。用不用缓存，结果应当一致（只差极小的数值误差）。

05

末尾加一句 vs 改开头一个数：哪个让缓存作废？

往后加 → 旧缓存照用；改前面 → 改动处之后都得重算。

这叫 causal attention：前面的字看不到后面的字，所以末尾追加不会改变前面已经算好的东西。

07

同一份文档，换个问题，还能接着用吗？

开头一模一样 → 跳过重复的 prefill；开头变了 → 从变的地方重算。

Prefill

一个计算阶段把 prompt 读一遍

KV cache

存下来的东西每个位置的 K/V

Prefix caching

一种复用策略开头相同，就用现成的 K/V

复用要同时满足：开头的 token 完全一样、模型和设置兼容、缓存还没被清掉。新问题仍要 prefill，新回答仍要一个字一个字写——详见 Prefill 与 Decode。没开 prefix caching，普通生成也照样用 KV cache。

08

还能换个存法吗？

前面都是「每层存自己的 K/V」。DeepSeek-V4.1-Flash 换了个思路：

一份 global KV 喂好多层；一个向量既当 K 又当 V。

读 10 万个 TOKEN · ①Encoder 读完整份 prompt，备好 global KV。
读 10 万个 TOKEN · ②Decoder 只重算最后 128 个 token，重建 local 状态；更早的内容靠 global KV 读到。

以上依据原文对 DeepSeek-V4.1-Flash 的介绍，图为示意。模型仍保留 local cache、indexer state 等其他状态；生成新字时，新输入仍要经过 encoder 和 decoder。
