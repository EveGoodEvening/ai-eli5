PAGEDATTENTION · vLLM

How can the same GPU
handle up to 4× the work?

By turning GPU memory from a row of reserved seats into a book whose pages can be stored anywhere.

01 The model’s notebook

For every new token,
the model first looks back.

To avoid recomputing earlier tokens, the model saves notes in GPU memory. This notebook is the KV cache. The longer the text, the thicker the notebook.

02 The old approach’s problem

If you do not know the final length,
you reserve a whole row.

The notes must occupy one continuous stretch, reserved for the maximum possible length. Most seats stay empty, yet other requests cannot use them.

03 An old idea, borrowed

This problem?
Operating systems solved it decades ago.

Computers use “paging”: split memory into small pages. A program sees a tidy sequence, while the physical pages can be scattered. A table maps one to the other.

04 PagedAttention

Split the notes into small blocks,
Allocate a block only when needed.

In this example, each block holds 16 tokens. Request another when it fills up; the blocks need not sit together. A block table tracks where each request’s blocks are stored.

05 A bonus

If the beginnings match,
store them once.

Generating three candidate answers from the same prompt? They share the initial blocks of notes. Only when a shared block must change is a separate copy needed.

06 The result

Turn the saved space
into more people served at once.

Less wasted memory lets one GPU process more requests together. vLLM is an open-source inference engine that uses this approach to serve language models.

Three terms

KV CACHE
The model’s notebook: cached keys and values for earlier tokens let later steps reuse prior work. It can consume a large share of GPU memory.
PAGEDATTENTION
A way to split the notebook into fixed-size blocks, store them separately, and track them with a table. “Paged” comes from operating system paging.
vLLM
An open-source inference engine that uses this approach. Many open-model API services run on it.
