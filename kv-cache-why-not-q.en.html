LLM inference · KV Cache

Why keep K and V, but let Q go?

Each time an AI writes a token, it looks back at every token before it. The KV cache stores what that look-back needs.

A token is a small chunk of text — roughly a word or part of one.

01

Does every new token mean recomputing everything?

No. Computed K/V stay put; each new token computes only its own.

First the model reads the input “The sky is” (prefill): the K/V for all 3 tokens are computed together and cached. It picks the first new token, “blue” — which has no K/V yet. Those are computed only when “blue” is fed back in.

Old tokens’ K/V are computed once, used again and again; each step computes just one new set.

02

What are Q, K, and V?

Inside an attention layer, every token is turned into three things.

The new token matches its Q against every token’s K; the better the match, the more of that token’s V it takes.

03 · THE KEY IDEA

Why keep K/V, but not Q?

Draw “who reads whom” at each step as a table:

The blue row: the Q of “blue” is used once. The green column: the K/V of “sky” is read by every later token.

Q is used once → no need to store it. K/V will be read again → store them. That’s why it’s called a KV cache.

04

What actually happens when a new token comes in?

Zoom in on the moment “blue” is fed back in, looking at a single attention head:

Then q leaves the stage; k and v stay on the shelf for the next token to read.

Because k and v enter the cache first, q can also attend to “blue” itself. The head’s output still passes through many later computations before it becomes scores for the next token. With or without the cache, the results should match (up to tiny numerical differences).

05

Add a line at the end vs change a number at the start: which breaks the cache?

Add to the end → the old cache still works; change something earlier → recompute from that point on.

This is causal attention: earlier tokens can’t see later ones, so appending at the end can’t change what was already computed.

07

Same document, new question: can the cache be reused?

Identical start → skip the repeated prefill; different start → recompute from where it changes.

Reuse needs all three: identical starting tokens, a compatible model and settings, and a cache that hasn’t been evicted. The new question still needs prefill, and the new answer is still written token by token — see Prefill and Decode. Even without prefix caching, ordinary generation still uses the KV cache.

08

Can K/V be stored a different way?

So far, every layer stores its own K/V. DeepSeek-V4.1-Flash takes another approach:

One global KV feeds many layers; one vector serves as both K and V.

READING 100K TOKENS · ①The encoder reads the whole prompt and prepares the global KV.
READING 100K TOKENS · ②The decoder reprocesses only the last 128 tokens to rebuild local state; earlier content is reached through the global KV.

Based on the source article’s description of DeepSeek-V4.1-Flash; the diagram is schematic. The model still keeps other state such as local caches and indexer state, and new input still passes through both the encoder and the decoder when generating.
