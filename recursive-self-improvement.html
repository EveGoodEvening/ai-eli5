Recursive self-improvement

A machine that builds a better machine.

Then that machine does the same thing.

Scroll ↓

01

Start with a machine that's good at one job: making machines.

02

So point it at itself.

Version 1 designs version 2. Version 2 is a little better.

03

Here's the twist: the thing it improved was its own building skill.

Version 2 doesn't just work better. It builds better. So version 3 arrives sooner, and is a bigger jump.

04

And now it's a loop that feeds itself.

Watch the lap get quicker each time around.

05

Nothing, nothing, nothing — then everything at once.

Each step is a bit bigger than the last. That shape stays boring for a long time, then goes almost straight up.

06

That's the whole idea.

Improvement that improves the thing doing the improving.

07

Which is why people argue about it.

The hope

Problems that would take humans centuries — diseases, materials, energy — get solved in a hurry.

The worry

If it speeds up faster than people can check it, nobody gets time to notice a mistake, or to stop it.

08

Does it actually happen?

Tiny versions, yes: a chess program that trains by playing itself, or a compiler used to build a better compiler. The dramatic version — a machine racing away on its own — has never been observed. It's a prediction, and experts disagree hard about whether it's coming, and how fast.

In one line: recursive self-improvement is what happens when a system gets better at getting better — so progress compounds instead of adding up.
